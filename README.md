# ⚔️ OPERATION: CODE WARRIOR

**One war game. Built in stages. Each stage teaches you new coding weapons.**

You are a non-technical recruit today. By the final stage you will be a
commander who can read, write, and secure real code. We learn by building
**one game that grows** — a war campaign — because your brain remembers
*stories and missions* far better than dry theory.

---

## 🎖️ How this works (read this first)

- Every **Stage** is one Python file you can run on your phone
  (Pydroid 3 app) or in a browser (replit.com — free, no install).
- The code is full of comments (lines starting with `#`). Comments are
  notes for humans — the computer ignores them. **Read them like a field
  manual.**
- Technical words appear in CAPITALS the first time (e.g. VARIABLE,
  LOOP). Say them out loud. That's how you become fluent in "tech speak".
- Every stage ends with a **🛡️ SECURITY DEBRIEF** — how the coding idea
  you just learned connects to real-world hacking and defense.
  Full details live in [`SECURITY-BRIEFING.md`](SECURITY-BRIEFING.md).

**The golden rule of learning to code: type it, break it, fix it.**
Don't just read. Change a number. Run it. See what explodes.

## 🗺️ THE CAMPAIGN MAP (basics ➜ advanced)

| Stage | Mission | Coding weapons you unlock | Security debrief |
|-------|---------|---------------------------|------------------|
| **1** ✅ | **Artillery Strike** — find and destroy a hidden enemy bunker | variables, input/output, loops, if/else, functions, modules, try/except | Never trust input — the #1 rule that stops most hacks |
| 2 | **Supply Lines** — manage ammo, fuel and rations | lists, dictionaries, for-loops | How malware hides in data; why file downloads are dangerous |
| 3 | **Build Your Battalion** — infantry, tanks, snipers with different powers | classes & objects (OOP) | Access control — why your PC asks "Run as administrator?" |
| 4 | **War Diary** — save and load your campaign progress | files, JSON, error handling | Viruses & trojans — how bad files infect a PC; backups as your shield |
| 5 | **Enemy AI** — the computer fights back with strategy | algorithms, randomness, game state | Encryption — scrambling messages so spies can't read them |
| 6 | **Allied Comms** — two players battle over a network | sockets, client/server basics | Firewalls, ports, and how hackers scan for open doors |
| 7 | **Command Center Online** — the game becomes a website | web server (Flask), HTML basics | Server hardening, SQL injection, HTTPS — securing PC ➜ server |

Each stage reuses everything from the previous one. Repetition with
purpose = remembering without effort.

## 📖 Stage 1 glossary — your first tech vocabulary

| Word | Battlefield meaning |
|------|--------------------|
| **PROGRAM** | The full battle plan — a list of orders the computer follows top to bottom |
| **VARIABLE** | A labeled ammo crate — a name that stores a value you can change |
| **STRING** | Text data, always in quotes: `"Fire!"` |
| **INTEGER** | A whole number: `42` |
| **FUNCTION** | A drilled maneuver — a named block of orders you can execute on command |
| **MODULE** | An allied unit — pre-written code you import instead of writing yourself |
| **LOOP** | A patrol route — repeat orders until told to stop |
| **CONDITIONAL (if/elif/else)** | A fork in the road — do this OR that, depending on the situation |
| **BOOLEAN** | A switch with only two positions: `True` or `False` |
| **INPUT VALIDATION** | Checking ID at the gate — never trust what a user types |
| **BUG** | A mistake in your orders that makes the plan fail |
| **CRASH** | The program dies mid-battle because of an unhandled error |

## 🛡️ Why security is baked into every stage

Every program you'll ever write is a fort. The moment it accepts input
from the outside world — a typed guess, a file, a network message — it
has a **gate**, and gates are where attackers strike. Learning to code
and learning to defend are the same skill viewed from opposite sides of
the wall. Start with [`SECURITY-BRIEFING.md`](SECURITY-BRIEFING.md)
after you've played Stage 1.
